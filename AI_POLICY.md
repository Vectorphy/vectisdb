# AI policy for VectisDB

Author: Pranav Dilip Dudhal (Vectorphy)

VectisDB is an experimental research and prototyping project. I designed the architecture, the benchmarking setup, the ablation matrix parameters, and the overall system orchestration. I did not write most of the code. Nearly all of the implementation, including the CUDA execution integration and the shell hooks, was generated by AI tools from my prompts.

## Tools and models used

I built it with Claude Code, Antigravity (IDE), and Codex, with my own workflows and skills set up in each. Kimi and Z Code did separate review and audit passes with their own workflows. Model names are as of September 2026.

- Anthropic: Claude Sonnet 5, Opus 5, and Fable 5
- Google: Gemini 3.8 Flash and Gemini 3 Pro
- OpenAI: ChatGPT 5.6 Sol, 5.6 Luna, and 5.6 Terra
- Moonshot: Kimi K3
- Z.ai: GLM 5.3 and GLM 5.3 Flash

## What this means for you

What matters here is the design: the benchmarking structure and the multi-variable evaluation built around the TPC-H SF 16 test harness, which is the part I planned and directed myself. The code itself came out of repeated prompting.

I would rather say so plainly. This repo is a case study in AI-assisted systems prototyping, not a hand-written database kernel. Keep that in mind if you fork it or build on it.

Audit and test the code yourself before you rely on it, especially the CUDA kernels and memory allocators, plus the DuckDB integration code. It is not production-ready and comes with no warranty; see the repository's license. Testing so far is thin. Every result comes from one GeForce GTX 1650 machine, most benchmark suites were run only once, and the FP32 fast-math results have no error analysis behind them.
